## DLP: escape runs and non-ASCII decoded text

Two holes left after v0.3.1, both found by the same external test:

- A body that quotes the invisible or fullwidth form as an escaped backslash (`\\u200b`, `"\\u200b"` in JSON) or that
  carries several backslashes before `u` left a backslash between the digits after decoding, so the card pattern did
  not match. Any run of backslashes before `uXXXX` is now decoded as one escape.
- Base64 of a card broken by real invisible characters was decoded but then discarded as "binary" because the check
  counted ASCII bytes only. A decoded blob is now judged by its runes, so text carrying invisible formatting is
  scanned (and normalized) instead of skipped.
